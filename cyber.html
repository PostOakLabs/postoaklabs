Cyber

Security you can verify from the hash up.

We run public finance tools and an MCP server, so we keep controls we can show you. This page lists what is in place today: proofs, receipts, logs, pinned builds and a way to report a problem.

  • 2,575 pinned golden hashes in CI
  • 0 network calls from tool pages after load
  • RFC 9116 security.txt on AINumbers

Nine controls

What we do and how to check it

01 · Proof

Proven computation

Calculation nodes in the AINumbers estate carry zero-knowledge receipts, produced with the RISC Zero zkVM and Groth16 over BN254. 667 nodes carry a proof.

  • A public coverage gate fails the build if a node loses its proof.
  • Proving runs on our own GPUs.
02 · Receipts

Deterministic receipts

Every result carries an execution hash: SHA-256 over RFC 8785 (JCS) canonical JSON of the policy parameters and the output.

  • One shared module is used by both the website and the MCP server.
  • 2,575 golden hashes are pinned and re-verified in CI.
  • Ad-hoc hashing is linted out.
03 · Verification

Formal methods and tests

A machine-checked Dafny proof covers a Regulation Z APR kernel. A public proof count is coming.

  • A small formal-verification pilot: its badges drop automatically when a kernel's digest changes.
  • A property-test floor on every kernel.
  • Nightly mutation testing.
04 · Logs

Transparency logs and timestamps

Errata and lineage checkpoints are registered in a public Sigsum transparency log with witness cosignatures. Other transparency logs are not yet in use.

  • anchor.ainumbers.co runs in the browser and timestamps a hash against RFC 3161 authorities and OpenTimestamps, using pinned roots.
  • It reaches them through a stateless relay.
05 · Egress

Pages that stay offline

Tool pages are written to make no network calls after load, and a Content-Security-Policy with connect-src 'none' backs that up.

  • The policy is delivered in a meta tag and still allows inline scripts, so it is a second line of defence, not the primary control.
  • No client storage and no personal data.
  • Egress is checked on both the source and the served site, on a schedule.
06 · Supply chain

Supply chain

  • All CI actions pinned to commit SHAs.
  • Workflow linting for injection and permissions.
  • A ruleset drift gate.
  • A merge queue with required checks.
  • Build provenance attestations.
  • SBOM and SLSA provenance on releases of one component.
07 · MCP

MCP server hardening

  • Unique tool names are enforced.
  • Typed JSON-RPC error envelopes carry request ids.
  • Malformed input fails fast and requests are rate limited.
  • A denial-of-service class in SSE id handling was found and fixed.
  • Negative-enforcement tests prove that a failing gate really stops a chain.
  • Adversarial testing is run against our own systems only.
08 · Disclosure

Disclosure

  • An RFC 9116 security.txt on the AINumbers site.
  • A published reporting policy.
  • A public postmortem log.
09 · Post-quantum

Post-quantum readiness

ML-DSA and SLH-DSA implementations are vendored and digest-pinned.

  • A cryptography inventory tracks where classical signatures are still in use.
Cyber services

Where we can help

We offer cyber work in the areas we have already done ourselves. Adversarial testing is limited to systems you own and authorize us to test.

Defensive

Find and validate weaknesses

  • Review of MCP servers and tool endpoints: input handling, error envelopes, rate limits, denial-of-service classes.
  • Validation of each finding before it is reported, so you get fewer false alarms.
Defensive

Receipts, hashing and signatures

  • Review of hashing and canonicalization schemes, and of how results are signed or timestamped.
  • Checks of transparency-log and timestamp setups, plus post-quantum signature inventories.
Defensive

Build pipelines and incidents

  • Hardening of CI: pinned actions, workflow linting, merge rules, build provenance.
  • Triage and written postmortems when something goes wrong.
Defensive

Malware and spam defense

  • Analysis of suspicious files and links, and the detection rules that come out of it.
  • Spam identification and prevention for forms, inboxes and public endpoints.
Investigative

Ransomware and on-chain forensics

  • Tracing payment flows on public blockchains and screening for sanctions exposure.
  • Our founder has written on how ransomware uses cryptocurrency and how compliance tooling can counter it, and has spoken on the topic at industry panels.
Adversarial

Authorized testing

  • Penetration testing of MCP servers and browser-based tools that you own and have authorized us to test.
  • Written scope and rules of engagement before any testing begins.
